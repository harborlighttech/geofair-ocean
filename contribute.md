# Contribute a resource

The quickest way is the **[Suggest a resource]({{ site.github_repo }}/issues/new?template=new-resource.yml)** form on GitHub. It asks for the resource's title, link, a short description and a few choices from drop-down lists; a maintainer reviews the suggestion and, once accepted, it appears here within minutes of being merged.

## What makes a good entry

- **One resource per entry.** A course with many modules is one entry; a page that only lists other resources is not a resource.
- **Describe, don't promote.** The description (up to 2,000 characters) should say what the material covers, how long it takes and what the learner needs beforehand.
- **Link to a stable landing page**, ideally one with a DOI or handle.
- **Pick the lifecycle stages and research areas the material actually teaches**, not every topic it mentions.
- **Testimonials** are welcome: a sentence or two from someone who used the material, with their name and affiliation.

## Updating or retiring an entry

Use the **[Update a resource]({{ site.github_repo }}/issues/new?template=update-resource.yml)** form, or click *Suggest an edit* on the resource's page to edit its file directly. When a resource is no longer maintained, ask for it to be marked obsolete and, if there is a replacement, say which.

## For maintainers

Resource files live in `_resources/`, one Markdown file each, and are validated automatically. See `CONTRIBUTING.md` in the repository for the field reference and the review checklist.
